# Website Test Checklist

Use this checklist before presenting the project in a portfolio. Mark an item complete only after you have actually tested it.

## Basic checks
- [ ] Website opens in a desktop browser.
- [ ] Website opens on a phone or narrow browser window.
- [ ] All navigation links lead to the intended sections.
- [ ] All buttons respond as expected.
- [ ] No text is cut off or overlapping.
- [ ] Images and charts load correctly.

## Keyboard and accessibility checks
- [ ] Press Tab to move through interactive controls.
- [ ] The focused control is clearly visible.
- [ ] The “Skip to main content” link works.
- [ ] The page remains usable without a mouse.
- [ ] Result messages are visible and understandable.
- [ ] The educational-use notice is easy to find.

## Content and data checks
- [ ] Every statistic has a traceable source or is clearly labelled as illustrative.
- [ ] The original dataset and accession are recorded, if a dataset is used.
- [ ] The method used to calculate each statistic is documented.
- [ ] No claim says the demonstration is clinically validated unless independent evidence supports it.
- [ ] The page states that it is not a diagnostic or treatment tool.

## Known project status
- Website status: reported by project owner as opening successfully.
- Button checks: reported by project owner as completed.
- Dataset provenance: not verified; no original dataset is currently available.
- Remaining: complete the checks above and verify any data claims before presenting them as research findings.

## Reporting a problem
For each failed check, note:
1. What you clicked or tested.
2. What you expected to happen.
3. What actually happened.
4. Browser/device used.

Do not mark a check complete based on assumption alone.
